Vision par ordinateur

Recherche d’images par similarité (embeddings ResNet)

Repository GitHub

Problème & approche

L’utilisateur choisit une image de la base comme requête, ou en fait tirer une au hasard. Le système s’appuie sur des descripteurs et retourne les images les plus similaires selon une métrique. L’approche combine des descripteurs « classiques » (couleur, niveaux de gris, forme, texture), des descripteurs profonds (embeddings ResNet pré-calculés, lus depuis un fichier), des classes de vérité terrain, ainsi qu’une évaluation quantitative (précision / rappel).
La génération des descripteurs est déclenchée par des appels GET dédiés (par exemple /rvb666). Seule l’évaluation précision/rappel est exécutée en asynchrone.

Fonctionnalités clés

  • Tirage au hasard d’une image requête via l’interface web (pour ResNet, choix d’une classe puis tirage au sein de celle-ci) ; l’API accepte aussi un queryImage explicite
  • Modes de recherche : couleur / forme / texture / embeddings ResNet / classes de vérité terrain / combinaison pondérée
  • Résultats classés par score de similarité
  • Évaluation : courbes précision/rappel
  • Architecture modulaire pour ajouter facilement de nouveaux descripteurs

Compétences démontrées

  • Conception d’une architecture full-stack Angular / Spring Boot.
  • Développement d’une API REST pour la recherche multimédia.
  • Implémentation d’algorithmes de recherche par similarité d’images.
  • Extraction et comparaison de descripteurs visuels (couleur, niveaux de gris, forme et texture).
  • Recherche par similarité s’appuyant sur des embeddings ResNet.
  • Mise en œuvre d’une recherche vectorielle basée sur les plus proches voisins.
  • Combinaison et pondération de plusieurs métriques de similarité.
  • Exécution asynchrone de l’évaluation précision/rappel.
  • Évaluation des performances à l’aide d’indicateurs de précision et de rappel.
  • Conteneurisation et exécution reproductible avec Docker Compose.

Architecture

Organisation du projet

.
├── multimedias-ui/   # Frontend Angular
├── multimedias/      # Backend Spring Boot / Java
│  ├── ferecatu/      # Base10000/ : images et fichiers VT_*.txt (volume)
│  └── outputs/
│     ├── descripteurs/    # Descripteurs générés
│     └── precisionrappel/ # Résultats précision/rappel
└── compose.yaml

Exécution via Docker (démo reproductible)

  • Démarrer : docker compose -f compose.yaml up -d
  • Arrêter : docker compose -f compose.yaml down

Accès :

  • Frontend Angular : http://localhost:4200
  • Backend API : http://localhost:8087

API (exemples)

Le backend expose des points d’entrée en GET (pas d’envoi d’image par POST). Quelques-uns, tels qu’ils figurent dans le code du dépôt :

GET /similaritecouleur
    tire une image au hasard dans le dossier d’images
GET /recherchesimilaire?k=<entier>
    k images les plus proches de l’image tirée ci-dessus
GET /recherchesimilairetexture?queryImage=<nom>&k=<entier>
    k images proches selon la texture
GET /resnetclasses
GET /resnetimages?className=<classe>&queryImage=<nom>
    recherche avec les descripteurs ResNet
GET /precision-rappel/gris | /couleur | /gris-couleur-resnet
    évaluation précision/rappel

Exemple curl. Le dossier multimedias/ferecatu/ ne contient que .gitkeep dans le dépôt. Il faut y placer Base10000/images et la liste Base10000/Base10000_files.txt, puis appeler une première fois /rvb666 pour générer le descripteur couleur :

curl http://localhost:8087/rvb666
curl http://localhost:8087/similaritecouleur
curl "http://localhost:8087/recherchesimilaire?k=10"
